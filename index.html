Installation guide

Standard installation is fail-closed and does not enable production autonomous remediation.

Requirements

Linux + systemdGitPython 3.14 + venvNon-root service account

Clone and environment

git clone https://github.com/arivonto/AIRIV-Sentinel-OSS.git "$HOME/airiv/airiv-sentinel"
cd "$HOME/airiv/airiv-sentinel"
python3.14 -m venv venv
venv/bin/python -m pip install --upgrade pip
venv/bin/python -m pip install -r requirements-dev.txt

Validate

PYTHONPATH=. venv/bin/python -m compileall -q sentinel tests
python scripts/validate_project_docs.py
PYTHONPATH=. venv/bin/python -m pytest -q -p no:cacheprovider
bash scripts/public_release_secret_scan.sh

Foreground run

PYTHONPATH=. venv/bin/python -m sentinel

Use for startup validation; stop with Ctrl+C.

Dry-run systemd install

./scripts/install_systemd_service.sh \
  --repo "$PWD" \
  --python "$PWD/venv/bin/python"

Install + activate

sudo ./scripts/install_systemd_service.sh \
  --apply \
  --user "$USER" \
  --repo "$PWD" \
  --python "$PWD/venv/bin/python"
sudo systemctl enable --now airiv-sentinel.service
systemctl status airiv-sentinel.service --no-pager

Security boundary

Source remains auditable while private host topology that is unnecessary for safe use is minimized.

Repository controls

  • Fail-closed/default-deny remediation.
  • Minimal CI permissions.
  • High-confidence reachable-history credential scanning.
  • Secret-bearing filename rejection.
  • Curated public allowlist.
  • Markdown/HTML link and structure validation.
  • Documentation disclosure guard.
  • Independent private/public Git histories.
  • Exact-effect authorization and replay protection.
  • Independent post-effect verification.

Never publish

  • Credentials, API keys, passwords, tokens, or private keys.
  • Private runtime evidence or production incident stores.
  • Private host-control/authorization material.
  • Unnecessary private host identities, state locations, trigger refs, or topology.
  • Exploit details in public issues or logs.

Read SECURITY.md

No zero-bug claim: passing CI and security gates is strong evidence for the tested surface, not a mathematical guarantee against future defects or vulnerabilities.

AIRIV Sentinel Roadmap — locked foundation

The roadmap must build on these settled boundaries unless an explicit strategic architecture decision changes them.

Locked inputs

  1. Sentinel is the AIRIV Autonomous Commander and remains external to AIRIV Server.
  2. Commander retains final strategic authority.
  3. Safety remains fail-closed/default-deny.
  4. Remediation policy remains canonical ALLOW/DENY authority.
  5. Execution remains centralized through the execution boundary.
  6. Independent verification is required for consequential recovery claims.
  7. Evidence remains observable, durable, reconstructable, and auditable.
  8. AI agents are execution resources, not semantic authority.
  9. Replay protection and terminal uncertain-outcome handling remain mandatory.
  10. Autonomy expands only through explicit bounded target/action contracts.
  11. AIRIV-Sentinel remains Private / canonical source.
  12. AIRIV-Sentinel-OSS remains Public / curated open-source distribution.
  13. Public synchronization remains allowlisted, fail-closed, secret-scanned, disclosure-validated, and history-separated.
  14. Both domains maintain synchronized README.md + index.html surfaces.
  15. No convenience automation may introduce broad cross-repository credentials or broaden production authority.

Roadmap candidates — not commitments

  • Additional production targets with explicit per-target safety profiles.
  • Richer durable evidence indexing, retention, query, and unattended timelines.
  • Improved Commander handoff and unattended-incident summaries.
  • Verified AI-agent/provider integrations without semantic authority.
  • Canonical AIRIV Event + Job adapter integration.
  • Packaging, upgrade, rollback, and release hardening.
  • Controlled promotion of validated curated public snapshots.
  • Fleet/multi-host architecture after identity, authority, and evidence contracts.
  • Metrics, health, observability, and recovery improvements.
